# signature-auth
Сервис аутентификации, использующий анализ динамических характеристик рукописной подписи для биометрической проверки пользователя.


## API v1

Интерактивное описание API доступно в `/docs`, OpenAPI — в `/openapi.json`.
На этом этапе добавлены только маршруты и описание контракта. Новые обработчики
возвращают `501 Not Implemented`; проверка ключей, работа с БД и обработка подписей
будут реализованы отдельно. Форматы образца и ответов пока не зафиксированы схемами.

| Метод | Путь | Назначение | Успешный статус после реализации |
| --- | --- | --- | --- |
| POST | `/api/v1/users` | Регистрация интегратора по `username` | 201 |
| POST | `/api/v1/users/me/api-key` | Перевыпуск собственного API-ключа | 200 |
| POST | `/api/v1/signature-references` | Создание / замена эталона по `subject_id` и 10 образцам | 201 / 200 |
| GET | `/api/v1/signature-references` | Список своих эталонов | 200 |
| GET | `/api/v1/signature-references/{reference_id}` | Метаданные одного эталона | 200 |
| DELETE | `/api/v1/signature-references/{reference_id}` | Удаление эталона | 204 |
| POST | `/api/v1/signature-references/{reference_id}/verifications` | Сравнение с одним образцом | 200 |

При создании эталона JSON содержит `subject_id` и `samples`, при сравнении — `sample`.
В списке доступны query-параметры `subject_id`, `from`, `to`, `limit` (по умолчанию 20,
максимум 100) и `offset` (по умолчанию 0). Фильтр `subject_id` означает точное
совпадение, `from` и `to` ограничивают `created_at` включительно. В Python используются
`from_ = Query(alias="from")` и `to_ = Query(alias="to")`. Список сортируется по
`created_at` и `id` по убыванию.

Метаданные эталона: `id`, `subject_id`, `created_at`, `updated_at`.
Список возвращает `items`, `total`, `limit`, `offset`. Содержимое `data` не выдаётся.

Для перевыпуска ключа и всех операций с эталонами потребуется
`Authorization: Bearer <api_key>`. Владелец определяется по проверенному ключу;
`user_id` клиент не передаёт. Неизвестный или отсутствующий ключ — `401`, отключённый
пользователь — `403`. Чужой и отсутствующий эталоны — `404`; занятый `username` —
`409`; неверные параметры или тело запроса — `422`. Отрицательный результат
сравнения подписи — обычный ответ `200`.

Новый ключ выдаётся только при регистрации и перевыпуске; после перевыпуска прежний
перестаёт действовать. `is_active` меняет только владелец сервиса вне публичного API.
Служебная проверка состояния приложения остаётся доступна по `/api/healthcheck`.
